# 足球直播项目文档

更新日期：2026-10-22

## 产品范围

本项目只提供足球赛事直播：显示赛程与比赛状态、发现并选择比赛信号源、播放 HLS 直播，并在播放异常时执行恢复。Android、iOS、Windows 与网页端使用统一的产品名称“足球直播”。

健康检查、应用更新、队徽和播放中继属于直播运行保障。

## 客户端与身份

| 客户端 | 工程 | 说明 |
|---|---|---|
| Android TV | `android/` | 电视端赛事列表与直播播放 |
| Android 手机/平板 | `internal/mobile/` | 触屏端赛事列表与直播播放 |
| iOS | `ios/` | SwiftUI 赛事列表与直播播放 |
| Windows | `desktop/` | 启动本地后端并显示网页客户端 |
| 网页 | `tools/backend-src/www/` | 足球直播主页与播放器 |

GitHub 仓库名为 `football-live`；工程与产物名称使用 `FootballLive`；应用显示名称使用“足球直播”。为让既有安装继续升级并保留本地设置，Android applicationId、iOS Bundle ID、签名与更新身份、证书主体、数据库标识和客户端本地数据目录保持原值。不得只为改名而重置这些标识。

## 运行结构

- Android TV、Android 手机和平板以及 Windows 客户端在本机启动 Python 后端；客户端与后端通过本机 HTTP 通信。
- iOS 与网页客户端请求配置的足球直播服务。
- 后端公开接口只服务赛程/状态、逐场信号源解析、直播播放中继、队徽、健康检查和 APK 更新清单。未知及非直播接口返回 404。
- 播放器支持 HLS 与 TS 分片中继，并保留换线、重试和故障恢复所需的播放状态。
- 自托管服务只保留直播网页、健康检查、热更新校验与回报、应用更新对象存储和发布工具。旧数据库迁移记录与数据为升级兼容保留；每次迁移启动都会撤销旧功能的客户端 RPC、表和序列权限，只开放足球直播热更新接口。
- 网页静态资源归档使用持久卷 `/var/lib/mytv/web-assets`（`WEB_ASSET_ARCHIVE_HOST_PATH`）。备份时需包含该卷；恢复部署时将归档目录挂载回服务，避免已发布网页资源缺失。

## 构建与发布

仅在用户明确要求发布时执行发布流程。默认先验证，再按 `AGENTS.md` 指定顺序刷新后端产物、构建网页与客户端、上传更新包、更新本说明并提交推送。Compose 部署使用 `--remove-orphans`，会停止配置中已移除的后台服务容器；数据卷不随容器清理。部署后先检查 Nginx 配置，再重建 Nginx 容器并 reload，以重新挂载同步后的配置文件。网页资源归档会保留 `/web/app.js` 当前源码别名供版本校验；页面自身加载带哈希的脚本。不要在此流程之外分配发布版本、构建 Release 包、部署、上传、提交或推送。

发布前确认工作区干净，并检查仓库是否存在其他活动任务，避免把并行修改或未验证内容带入正式产物。改动后应分别核对网页资产、后端包与客户端内嵌文件的一致性。

## 直播排障

1. 先确认比赛有可用赛程记录，并检查对应信号源是否已开播。
2. 比较客户端收到的信号源与后端线路解析结果，区分上游无源、解析失败和客户端播放问题。
3. HLS 播放异常时同时检查播放清单、分片中继和播放器日志；网络错误不得直接认定为解码器问题。
4. 用稳定连续的真实直播流验证长时间播放。测试片段或模拟器通过不能替代实体电视上的解码、日志和持续播放证据。
5. 修改服务端配置前先阅读 `AGENTS.md` 与对应的 `.learnings/` 记录；不得把私钥、卡密、Cookie、服务密钥或长期令牌写入仓库。
