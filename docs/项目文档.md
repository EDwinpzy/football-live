浏览器直连 VPS 前需要先信任迁移 CA（`android/app/src/main/res/raw/mytv_migration_ca.pem`，`CN=My TV Migration CA`）；

网页版影视的**片源**由本机解析后生成的静态索引供给（`tools/build_vod_line_index.py` +
对象桶 `hotupdate/vod-lines.json`，见第二部分 §9.1），因为 VPS 出口到不了片源站 API，而家宽可以。

### 0.1 已知风险（当前未解决）

- **网页版片源覆盖取决于索引新旧**：VPS 出网访问 macCMS 系片源站（`www.hongniuzy2.com`、`www.haohankan.com`、
  `bfzyapi.com` 等）IPv4/IPv6 全部连接超时（实测连测 18 个采集站全 000），服务器侧实时匹配必为空。
  现在的主兜底是「本机解析好的静态索引」：由 `tools/build_vod_line_index.py` 生成、
  scp 到 `/srv/mytv/objects/hotupdate/vod-lines.json`，VPS 读它出线路（`OTV_VOD_LINE_INDEX_URL`），
  **不再依赖 CloudBase**（该链路已置 `OTV_VOD_CLOUD_FALLBACK=0`）。
  代价是：① 新片/冷门片要等下一次重建索引才有线路（索引命中率实测 262/565）；② 索引默认 30 天过期。
  App 端不受影响——设备取源在**本机网络**实时完成（`EmbeddedBackend` 起 `proxy.py`，`baseUrl=127.0.0.1`）。
- **VPS 也够不着部分视频 CDN**：片源分片（如 `hnts.ymuuy.com:65`、`c.baisiweiting.com:18443`）在 VPS 上超时，
  中继会 499。网页播放已改为「浏览器直连优先、失败回中继」绕开该问题；但**纯 http 直链仍只能走中继**，
  这类片源在网页版会失败（App 端不受影响）。
- 直播、搜索、目录、元数据接口不受上述问题影响，已在 VPS 上实测通过（直播源多在国内 IPTV 主机，VPS 可达）。

## 1. 产品概览

**My TV（OptimalTV 工程）**：Android 原生影视应用（TV 大屏 + 手机/平板双端）+ 云端网页版，
Kotlin + Jetpack Compose + Media3，tvOS 深色风格。影片卡片、详情和筛选以豆瓣目录为准，播放线路来自后台可管理的现有影视源；**后端打包进 app**（Chaquopy 内嵌 Python），每台设备直接访问公网内容源与播放源，无需自建业务服务器。商业化 = 卡密付费（公测版门控）。

### 2026-09-13 发布边界

- 本机是唯一代码整理、构建和 Git 发布入口；不再把云端服务器部署作为常规发布步骤。
- 后端与 `www/` 使用同一内容寻址 zip，在后台静默下载、SHA-256/结构校验后只重启 `:backend` 进程，App 前端不弹窗。
- Kotlin/Compose 等原生 UI 无法由 Python zip 替换，必须构建签名 APK 并交给 Android 系统安装器更新。
- 足球队标使用“内置映射优先 → football-logos.cc 在线补全 → 磁盘缓存 → TheSportsDB → 文字兜底”。当前项目按非商业粉丝项目使用该站资源，不把全量队标打包进 APK；后端保存已解析结果，站点不可用时仍保留现有回退链。

## 3. 端侧功能模块

### 3.1 影视点播与搜索

- 数据源 hhkan；搜索支持拼音输入法（AOSP 谷歌拼音解码器 `cpp/pinyinime`）与首字母联想
  （构建期两张 asset 表：汉字首字母 + 全库片名快照，`tools/gen_pinyin_initials.py` / `gen_pinyin_titles.py`）。
- **hhkan 云端容灾（2026-09-09）**：好好看仍是唯一目录/卡片/元数据源。本地和 Android 优先实时抓取；
  腾讯云数据中心出口被源站风控时读取构建期 `hhkan_snapshot.json`（当前 626 卡、259 完整详情），固定三栏目、
  搜索、筛选、分页与详情均不切换目录来源。5 分钟熔断器保证同实例只做一次失败探测，到期半开恢复；快照不访问 PG。
- **macCMS 播放补充池（2026-09-09 需求⑮）**：暴风、极速、金鹰、虎牙、豪华、红牛、速播、360 共 8 个
  T1 源，仅在好好看详情之后按同名影片追加播放线路；不得生成卡片、替换目录或改变分类。站级并行测速排序
  （5min）+ 故障自动换站；线路级清晰度排序（实读 RESOLUTION，死线沉底）；pid≥100 使用站点命名空间，
  ≥720p 线路优先供播放器自动选择。补线总开关 env `OTV_ENRICH=0` 可关闭。
  **未能接入的 3 个候选源**（2026-09-08 探测结论）：nnyy.in（Cloudflare TLS 指纹墙，Python 出站必被重置）、
  NO视频 novipnoad.uk（player iframe pkey 服务端校验需真实浏览器会话，curl/无浏览器必「页面已过期」；
  播放器 URL 形态 `https://player.novipnoad.uk/v1/?url={vid}&pkey=` 已逆出，混淆 play.js 为 base91+字串数组）、
  SA视频 lsjys11.com（Nuxt SPA + API 响应体加密 + requestid/time 设备指纹头，945KB 混淆 crypto 分块，
  破解与维护成本过高；同内容 MacCMS 池已覆盖）。
- **片库板块 LazyColumn 的 item key 必须用板块名**（`lib-sec-{sec.name}-r{ri}`，2026-09-07 需求①
  跳行事故教训）：三块到货顺序与 blockOrder 展示顺序不一致（最近热门最慢却排第 0），序号 key
  会让迟到板块的插入触发全部行 item 重建 → 聚焦节点销毁、焦点乱甩（TV 端「光标跳行」的根因）。
  TV 与移动版同款布局同规则。

### 3.2 卫视直播与 IPTV

- 卫视直播：精编频道表内置（assets `iptv_curated.m3u`），台标本地图标（60 真实台标，
  `tools/build_logo_assets.py` 生成，序号=已落盘最大+1 防串台；暗标白化 normalize_logo），
  自动补源、多源备份无感切换。
- IPTV 电视：SOURCES = 云端桶 latest（首位）+ Guovin（gh-proxy/jsdelivr）+ vbskycn；快照落
  `files/iptv_snapshot.m3u` 先读秒上屏；刷新节流 ≤30min。
- 测速换台（v1.19）：`rankUrls()` TTFB 测速排序起播即最快线；BUFFERING>3.5s 且备线分值
  <0.55×当前 → 无感切换；侧边栏 60s 周期探测组内前 40 线路。
- 播放健壮性：首帧看门狗（READY 15s 无首帧→切 VLC）；fatalMsg 12s 未恢复自动跳台（环形，
  连续 3 次上限）；ac3/eac3/dts 音轨自动转 VLC。
- **SSRF 双层校验** `data/source/UrlGuard.kt`：仅 http/https、拒私网/环回/IPv4-mapped，
  `assertPublicResolved()` DNS 全 A 记录私网则拒；列表拉取侧 + 起播侧两层（云端版本同款内联实现）。

### 3.3 播放引擎

- 三级回退：Media3 硬解 → 中继 HLS → libVLC；点播直播共用会话代数管理（engineEpoch）。
- 直播 HLS 经本机中继（签名 ~9 分钟轮换 + 90s 续签热切换）；解密中继 `StreamDecryptServer`
  （2026-09-07 起 **3-WebView 解密池**：信号量+槽位并发，串行→3.2× 吞吐，替代单实例全局锁）。
- 足球解密三级分发：端内 QuickJS HTTP bridge（:8091）/ 本地 node / 云函数 `decrypt_python.py`。
- **解密池自愈（2026-09-08 需求⑬）**：StreamDecryptServer 的 WebView 加 `WebViewClient.onRenderProcessGone`
  → 销毁清槽懒重建（返回 true）；12s 零回调僵死检测兜底（渲染进程活着但页面级僵死的形态）；
  poll/loadData 全面 runCatching。修复前形态：反复加载混淆页数小时后渲染进程崩溃 → 僵死 WebView 永久
  留池 → 每次解密 12s 超时 → 三槽全僵 = 「半小时后所有信号源失效」。MuMu 实测 kill -9 渲染进程后
  下一次解密 0.5s 恢复。
- **足球直播信号源行为（2026-09-07 需求②③）**：① 起播快路径只解析首选源（1 次频道页+播放器页
  +解密）→ 立即起播；其余源 `streamUrlsIncremental` **到货即上屏**（不等最慢源，旧行为是
  awaitAll 全源到齐才渲染选择条）；② 首选源 = 上次手动选择的信号源（`liveLastSrc` 持久化；
  网页版 localStorage 同款），记忆源不在本场动态线路表时回退 bb；手动切源即保存，自动故障
  换线不污染记忆。

### 3.5 卡密付费体系

- **码制**：`OTV-XXXXX-XXXXX`（10 有效字符，32 键字母表剔除 0/O/1/I）。套餐：monthly 30 天
  ¥9.9 / quarterly 90 天 ¥29.9 / yearly 365 天 ¥99.9 / lifetime 终身 ¥128（+weekly 周卡 7 天，
  非卖品；周卡改动需四层同步：LicenseManager.PLAN_DAYS、license_gen.py、后台 UI、
  **PG licenses_plan_check 约束**，漏改则入库报 DATABASE_23514）。
- **安全模型**：ECDSA P-256 + SHA256；**私钥只在本机**（`tools/keys/private_key.pem`），
  云端只查表/计数/原样返回票据——云端被黑也伪造不了授权。票据 `{v,code,plan,days,issued,nonce,sig}`，
  canonical 串 `v|code|plan|days|issued|nonce` 本地验签。
- **协议 v2 与统一到期**：PostgreSQL 在首次激活时写入唯一 `activated_at` 和 `expire_at`；第二台设备
  只绑定，不重新计时。续费保留原卡为会员主卡，只延长统一 `expire_at`，新续费卡写入
  `redeemed_at/redeemed_to` 后不可重复使用；公式仍为 `max(expire_at, now) + days`。
- **设备绑定**：服务端只认完整 64 位小写摘要。Android 为
  `SHA256(ANDROID_ID|packageName|Build.MODEL)`；Web 为 `SHA256(持久随机种子|origin)`；maxDev=2，
  同码同摘要幂等，`verify` 不会偷偷新增设备。
- **联网复验与 24 小时宽限**：App/Web 每 6 小时、启动/回前台/播放前复验。403/404/405/406
  明确业务拒绝立即失效；断网、超时或 5xx 从最近一次成功复验起保留最多 24 小时，之后暂停播放，
  再次成功复验自动恢复。服务端 `serverNow/activatedAt/expireAt` 是时间权威，旧版最大时间戳账本和
  HTTP Date 校时已移除。
- **门控**：全量门控（未激活禁看一切，路由层 `LicensePlayerGate` + 播放页二重校验）；
  DataStore `license.preferences_pb` 持久化。
- 收款发货外包爱发电（主）/面包多（备）。

#### 3.2.1 APK 版本号规则（2026-09-22 重置）

用户于 2026-09-22 要求把 APK 版本与更新记录清零，版本号从 **V1.0** 重新开始、每版 **+0.1**：

| | 规则 | 例 |
|---|---|---|
| `versionName` | 界面展示用，`V主版本.次版本`，每版 +0.1 | V1.0 → V1.1 → V1.2 |
| `versionCode` | `主版本 × 100 + 次版本 × 10` | V1.0=100、V1.1=110、V1.2=120、V2.0=200 |

- `versionCode` 必须**严格递增**：客户端 `ApkUpdatePolicy.decide` 只比较它（`manifest.versionCode <= 本机`
  即视为无更新），Android 系统也不允许低版本覆盖安装。V1.0 取 100 而非 10，就是为了高于重置前的 42，
  已装 1.4x 的设备仍能收到 V1.0 的更新提示。
- 默认值写在两个 `app/build.gradle`（`android/`、`internal/mobile/`），也可用 `-PapkVersionCode=` /
  `-PapkVersionName=` 临时覆盖。后台「版本发布 → APK 更新」页会按当前公开清单自动预填下一版的 +0.1 / +10。
- 次版本满 9 后进主版本（V1.9 → V2.0，code 190 → 200），避免与 `×100 + ×10` 编码冲突。

## 8. 正式域名与证书（自建入口）

⛔ **原「CloudBase 兼容入口自定义域名」一节已退役，不可执行。** CloudBase 环境与其域名/路由接口都已下线，
下面的 `cloudbase login` / `domains add` / `routes add` 等命令不再有作用对象，仅作历史留档：

> 历史做法是在 CloudBase 环境上绑定一个已备案的自定义域名（DNS CNAME 指向平台，
> 再用 `cloudbase routes add` 把 `/activate`、`/hotupdate`、`/iptv`、`/web` 四条路由指到云函数），
> 目的是绕开默认 `*.tcloudbase.com` 域名在部分 QQ/X5 内核浏览器上的“风险提醒”中间页。

**现在的做法**：正式域名直接绑在自建 VPS 的 nginx 上（`deploy/selfhosted/nginx.conf`），
用公共 CA 证书（`/srv/mytv/secrets/tls/server.crt` + `server.key`），不再需要任何平台侧域名绑定。

- 备案与 DNS：把正式域名 A 记录指向 VPS 公网 IP，签发公共 CA 证书后放入
  `/srv/mytv/secrets/tls/`，然后 `docker compose -f deploy/selfhosted/compose.yaml up -d --build nginx`；
- Release 入口门槛：两套 APK 的 Release 构建**必须**显式传入这个正式域名
  （`-PapiBaseUrl=https://<正式域名>/api/` 或环境变量 `OTV_RELEASE_API_BASE_URL`），
  否则构建直接失败——IP 与迁移 CA 只允许 Debug 联调，正式包一律拒绝
  （规则与测试见 `tools/tests/test_release_api_origin_contract.py`）；
- 路径口径：APK 侧 `apiBaseUrl` 必须是 `/api/` 形式，nginx 侧再把 `/api/*` 转发到各后端服务；
  当前 nginx 仍按根路径（`/activate`、`/hotupdate`、`/iptv/`、`/web/`、`/admin/`）分发，
  切到 `/api/` 前缀时两处必须一起改并同步 Release 门槛的期望值。

### 9.3 影视元数据中心（2026-09-24 起）

元数据中心把「抓取 → 归一化 → 匹配 → 发布」从请求链路上挪下来，跑在同一台 VPS 上；设备端拿到的是一份带版本号的
SQLite 包，`mytv_id` 永久不变，原有 `douban:<id>` 引用继续可用。

```text
/srv/mytv/metadata/snapshots/douban_snapshot.json   源快照（可由 VPS 自行刷新）
/srv/mytv/metadata/db/metadata-latest.sqlite        查询服务读取的当前库
/srv/mytv/objects/hotupdate/metadata/               公开产物：manifest.json、metadata-v<版本>.sqlite.gz、delta-*.sql.gz
```

运维命令（都在 `/srv/mytv` 下执行）：

```sh
docker compose -f deploy/selfhosted/compose.yaml --profile ops run --rm metadata-builder rebuild   # 重建并发布
docker compose -f deploy/selfhosted/compose.yaml --profile ops run --rm metadata-builder stats     # 看当前库与 manifest
docker compose -f deploy/selfhosted/compose.yaml --profile ops run --rm metadata-builder verify    # 只校验线上产物哈希
systemctl start mytv-metadata-refresh.service                                                     # 手动跑一次全流程
systemctl list-timers mytv-metadata-refresh.timer                                                 # 下次自动运行时间
```

- 版本号规则 `YYYYMMDDnn`（Asia/Shanghai）；内容没变时 `rebuild` 输出 `result=unchanged`，不产生新版本。
- 公开只读入口：`/metadata/health`、`/metadata/manifest.json`、`/metadata/search?q=`、`/metadata/<mytv_id>`。
- 服务版本：`metadata-api` 容器（内部 8094，由 Nginx 转发 `/metadata/`）；数据库只在容器网络内读取，不新开端口。
- 浏览器直连 `https://103.236.97.137:35208/metadata/...` 需要先信任迁移 CA；命令行用 `curl --cacert` 或 `-k` 验证。
- 抓取失败不影响发布：刷新脚本保留上一份快照继续重建，短期断源不会把线上影视搬空。
- **热更上传必须直连 VPS**：CloudBase 后台桥读上游超时 30s，而热更提交要读回 40MB 分片重组，必然超时
  （`{"ret":502,"msg":"upstream_unavailable"}`）。命令：
  `node 后台管理系统/scripts/ops/hu-upload.mjs --site https://103.236.97.137:35208 --version <n> --name "..." --notes "..."`，
  并给 Node 指定迁移 CA：`NODE_EXTRA_CA_CERTS=android/app/src/main/res/raw/mytv_migration_ca.pem`。
