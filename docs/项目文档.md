# 球迹直播项目文档

更新日期：2026-10-31

## 产品范围

“球迹直播”（工程品牌 `QiuJiLive`）只交付两个 Android 客户端：Android TV 版和 Android 移动版。两端都提供足球赛程、比赛状态、信号源选择、HLS 直播播放和播放故障恢复；不再交付 Windows、iOS 或独立网页客户端。

服务器上的 `www/` 与 `/web/` 只作为应用更新清单、健康检查、静态资源归档和历史兼容入口保留，不属于第三个客户端，也不作为产品验收面。清理服务器时必须保留 TV/移动版更新链路和客户端内嵌后端需要的资源。

## 客户端与稳定身份

| 客户端 | 工程 | applicationId | 说明 |
|---|---|---|---|
| Android TV | `android/` | `com.qiubo.optimaltv.public` | 电视端遥控焦点导航与直播播放 |
| Android 移动版 | `internal/mobile/` | `com.qiubo.optimaltv.mobile.public` | 手机/平板触摸导航与直播播放 |

品牌名称已经统一为：用户显示名“球迹直播”、工程品牌 `QiuJiLive`、GitHub 仓库 `EDwinpzy/football-live`。2026-10-31 完成本地项目目录、应用显示名、图标、构建产物名和文档的品牌更新；GitHub 仓库名保持不变，以维持既有远端地址。

为保证既有安装可以升级，以下身份不得因改名而改变：applicationId、namespace、签名 keystore/alias、更新协议和公开 URL、对象桶/清单路径、自托管环境 ID、Room 数据库名、DataStore/SharedPreferences 键、迁移证书及本地数据目录。

## 运行结构

- TV 版与移动版启动各自 APK 内嵌的 Python 后端，通过本机 HTTP 请求赛程、信号源、队徽和中继接口。
- 播放器支持 HLS 与 TS 分片中继，并保留换线、重试、首帧恢复和长播放健康检查状态。
- 自托管服务只维护健康检查、热更新校验/回报、TV/移动版 APK 清单和对象存储；旧数据库迁移文件仅用于升级兼容，不能重新开放已删除的影视、IPTV、会员或后台业务。
- `/web/apk-update/tv.json` 与 `/web/apk-update/mobile.json` 是现有客户端更新协议的一部分，不能因为移除网页客户端而删除。
- `www/assets/football/` 的队徽/海报资源仍可能由原生客户端通过本机后端请求，未完成引用核对前不能删除。

## TV 遥控与移动触摸验收

TV 使用 x86_64 的 `emulator-5556` 或实体电视验收；不能用不匹配 ABI 的模拟器代替。新包安装后必须确认：

1. 首次打开后焦点落在“立即观看”、联赛筛选或“重新加载”，不落在已删除的顶部标签栏。
2. 上、下、左、右每次都能移动到真实内容控件；OK 能进入比赛，返回能回到首页。
3. 更新弹窗关闭后首个方向键不需要“唤醒”焦点，页面立即可操作。
4. 播放页能显示首帧，切换信号源、重试和返回路径不崩溃。

移动版至少验证竖屏和横屏的触摸滚动、联赛筛选、比赛点击、播放器信号源/返回控件及更新弹窗关闭后的整页触摸。

## 真实直播长时验收

必须使用当前源码重新构建并安装的 APK 和真实上游直播源；测试视频、旧 APK、首页截图或单元测试都不能替代实播验收。记录比赛 ID、线路 ID、开始/结束时间、周期截图、进程存活、`logcat -b crash`、播放健康日志和缓冲/恢复事件。

通过条件是连续累计 60 分钟：进程不退出、无 FATAL/AndroidRuntime 崩溃、无持续黑屏或冻结、无用户可见反复缓冲，并且相对直播边缘没有明显持续延迟。若一场比赛结束，必须切换到另一场真实比赛继续累计；找不到可播真实源时，验收状态必须写为“未完成”，不能宣称通过。

## 直播排障

本次用户验收口径（2026-10-25 更新）：必须同时测试多场不同比赛，不能以单场或同一比赛多开代替普适性验证。执行矩阵至少覆盖 3 场不同比赛、不同可用线路及 TV/移动版，每场连续观察 60 分钟；不得出现播放缓冲、冻结、退出、ANR 或闪退。延迟按用户确认的“相对同一上游原始直播信号，APP 额外延迟最多 5 秒，并且不累积”验收，使用同期画面对照及完整日志，播放器参数和进程存活不能单独证明通过。当前源站赛程仅 1 场正在直播，已结束或无源比赛不计入并行通过样本。

1. 先确认比赛在赛程中且有可用信号源。
2. 对比客户端收到的信号源、后端解析日志和中继请求，区分上游无源、解析失败与客户端播放失败。
3. HLS 异常时同时看清单、分片中继、播放器健康日志和 `logcat`；网络错误不能直接归因于解码器。
4. 任何长时播放结论都要注明设备、构建变体、真实源、起止时间和日志/截图路径。
5. 私钥、卡密、Cookie、服务密钥和长期令牌不得进入 Git、部署包或文档。
