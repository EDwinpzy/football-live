# My TV 后台“控制塔”重设计规格

## 1. 目标与边界

本次重设计把现有后台从普通三栏管理页替换为桌面宽屏优先的“控制塔”运维台。目标是让运维人员先看见系统状态，再进入当前工作域完成卡密、发布、公告和内容源操作。

保留：现有路由/Tab 切换、业务接口、数据协议、表格字段、表格排序、危险操作确认、底部 toast 回执、电视源/影视源编辑浮层。

不做：重写后端 API、引入前端框架、改变权限模型、创造新的业务指标、改变卡密和发布的实际语义。

## 2. 第一视口结构

### 顶部状态带

固定高度的状态带只承载产品标识、激活端点健康、热更/同步状态、当前时间和会话信息。它不承担页面标题或复杂操作，避免和主作业区争夺注意力。

### 左侧命令轨

按四个工作域组织现有入口：

- Observe：总览、激活日志
- Control：卡密、补货
- Publish：热更、公告
- Sources：电视源、影视源

当前入口保留原 `data-tab`，仅改变分组、选中态和视觉层级。窄屏变为横向滚动工作域条。

### 中央作业区

中央区域承载现有每个 section。总览页第一视口由三组真实 KPI、最近运维动作表和常用动作入口组成；其他 Tab 保持原表单/表格内容，只换成同一套控制塔容器、标题带和工具栏。

所有 `table.grid` 继续使用：

```css
white-space: nowrap;
overflow: hidden;
text-overflow: ellipsis;
```

窄屏由 `.gridwrap` 横向滚动承载完整列，不允许通过换行破坏字段对齐。

### 右侧信号板

右侧只放持续关注的运行信号：激活端点、热更存储/版本、电视源线路、下一次自动任务。信号板与业务数据同源，不添加新的接口；缺少数据时显示现有的加载/异常状态。

## 3. 视觉系统

视觉决策记录在根目录 `DESIGN.md`。核心规则是石墨蓝黑工作台、冷青当前态、绿/琥珀/红状态语义、边界线分层、中文无衬线 + 状态码等宽字体、克制圆角和低动效。

控制塔要有一个明确的主动作：进入页面时中央作业区先展示“最近运维动作”和健康信号，其他模块保持安静，不用每个卡片都做装饰性强调。

## 4. 响应式与可访问性

- ≥1280px：三段式控制塔，右侧信号板常驻。
- 921–1279px：左轨和中央区保留，信号板折叠为可展开状态条。
- ≤920px：左轨横向滚动，中央区单列，表格横向滚动，底部回执条保留。
- 保留键盘焦点可见、原生表单语义、按钮文字和现有 `aria-label`。
- 动效通过 `prefers-reduced-motion: reduce` 降级为即时状态切换。

## 5. 实施策略

1. 只重构 `tools/admin.html` 的 CSS、布局容器和必要的导航结构。
2. 将相同内容同步到 `cloudfunctions/otv-admin/admin.html`，保持云端函数源一致。
3. 不改动现有业务 JS，除非为新增容器查询或状态板复用现有状态节点必须做极小的 DOM 适配。
4. 先完成总览、卡密、日志三个高频工作域，再把同一套容器规则覆盖到补货、热更、公告、电视源、影视源。

## 6. 验证标准

- 桌面宽屏截图：控制塔第一视口结构清晰，信号板与中央表格不争夺层级。
- 窄屏截图：导航可达、表格单行且可横向滚动、表单不被截断。
- 两份 HTML 内联脚本可解析，现有测试保持通过。
- 真实浏览器验证总览、卡密、激活日志至少三条 Tab 切换和表格渲染。
- 视觉验证记录截图路径；未完成发布前不宣称 APK、热更或线上部署已验证。
