# My TV TV/移动端播放与目录性能设计

日期：2026-09-24  
状态：已由用户批准（2026-09-24）
依据：桌面全链路优化方案及 android、internal/mobile 两个工程。

## 1. 范围与约束

本轮支持 TV APK 与移动 APK。两工程中多个 data、repository、engine 和 recovery 文件逐字节相同，但 PlayerViewModel 与 UI 有平台差异。共享逻辑须同步实现并分别构建；保留移动端 DLNA/手势等功能和 TV 遥控焦点语义。

已发布旧 APK 不属于本轮兼容范围。当前受支持版本不调用 CloudBase。

## 2. 点播详情与首播

- 详情基础信息优先由当前本地目录/SQLite 显示，线路解析并行进行；详情不能因某个来源慢而空白。
- 按影片/集记录最近成功来源和内容引用，不持久化会过期的签名播放 URL；下次播放先复用该来源，同时后台刷新。
- 接入 Source Resolver 的 preferred/backups。preferred 可用时立即准备 Media3；其他线路继续解析并增量加入候选。
- 无 preferred 时等第一个可信结果并立即起播，不等待全部来源。匹配中、快路径失败、旧线路可用和真实暂不可用使用独立状态。
- 超时或短暂空响应不能直接变成最终 UNAVAILABLE；真正不可用时说明暂时无法播放并允许重试，不能伪造线路。
- 保留 HTTPS 直连优先；在直连不适用或失败时沿用现有 relay 回退。

## 3. 播放恢复与引擎回退

按错误类别恢复：

- 网络、HTTP、超时和 manifest 错误：准备健康备用源并换线；
- decoder、音轨/容器错误：优先切换 libVLC；
- 现有不支持音轨回退规则继续保留。

VOD first-frame watchdog 依据实际首帧而非仅 READY。启动 3–5s 时准备 backup，5–7s 执行可恢复换线，15s 为最终硬超时。BUFFERING 结合 buffer 增量、字节/分片进展、近期切线记录和 20–30s 冷却，避免短抖动造成切线循环。

长播每 5–10s 采集本地 position、buffered duration、playing/state、网络字节和 manifest/segment 最近成功时间。按 BUFFERING、buffer 不增长及无新分片的组合判定；逐级准备备用线、切线和换引擎。测速、metadata 刷新、日志及播放使用隔离的调度资源，避免全局锁阻塞播放器。

## 4. 目录、搜索与 Compose

- 将版本化 metadata SQLite 纳入目录、筛选、详情基础信息与搜索的本地读取路径；manifest 检查和增量更新放后台。
- 从 JSON catalog seed 迁移时保留可恢复回退。Room 中 favorites、history、progress 不丢失；schema 迁移具备版本检查、原子提交和损坏回退。
- 搜索按完全匹配、前缀、拼音、首字母、FTS 与模糊候选排序；大查询、拼音处理和图片解码都在后台。
- LazyColumn/LazyRow 使用稳定业务 ID。只修复仍使用 index 的动态列表；异步更新时保持 section 容器及焦点 key 稳定。
- 继续使用 Coil 内存/磁盘缓存和已有封面预取；按实测限制卡片尺寸、可见窗口和并发。图片加载完成不能改变卡片尺寸。
- TV 遥控器焦点机制保持集中式；移动端保留触控、旋转、DLNA 与播放手势。

## 5. 指标目标

- 有缓存时首页可操作 ≤ 1.0s；片库首屏 ≤ 1.2s；详情基础信息 ≤ 300ms。
- 点播放到首帧 P50 ≤ 2.0s、P95 ≤ 4.0s。
- 30 分钟异常中断率 < 0.5%，重缓冲占比 < 1%，自动换线恢复目标 1–3s。
- UI 严重卡顿帧 < 1%。检查 TV D-pad 连续 100 次、异步板块/图片到货、200 卡片滚动，以及移动端快滑、旋转、反复进出详情、seek 和音量/亮度手势。

指标须有真实设备、网络、内容和样本记录。统计样本不足时标记未验证，不手工补数。

## 6. 测试与截图

- 两工程分别运行 unit tests 与 release 编译；设备可用时分别运行 instrumentation suites。
- 为 Resolver/last-good/首帧/错误分类/恢复冷却/数据库升级补齐先失败后修复的测试。
- TV 1920×1080 emulator 覆盖主页、片库、详情、播放与焦点恢复；移动 1080×2400 emulator 覆盖片库、详情、播放器、旋转和移动端独有功能。
- 两端保存真实页面截图，关键内容已加载且目标行为可见；空白页/错误页不能作为通过证据。
- 播放矩阵覆盖电影、剧集、HLS、直链、1080p、低清旧源和稳定/高延迟/限速/丢包/短暂断网。每类至少覆盖 5 分钟与 30 分钟，2 小时长播使用代表性组合；不适用条件须标明。

## 7. 数据与安全

旧 APK 不作为回归目标；当前 TV/移动版本的设置、收藏、历史、进度和 license 数据不得因 Room/catalog migration 丢失。日志与持久缓存不保存完整临时播放凭证。
