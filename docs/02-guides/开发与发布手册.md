### 3.2 改 Kotlin/Compose 或播放器原生代码

先检查共享层：

```powershell
python tools/sync_shared.py
```

再分别构建，禁止两个工程并行构建：

```powershell

```

原生代码无法通过后端热更新替换，必须安装新 APK。

#### 3.2.1 APK 版本号规则（2026-09-22 重置）

用户于 2026-09-22 要求把 APK 版本与更新记录清零，版本号从 **V1.0** 重新开始、每版 **+0.1**：

| | 规则 | 例 |
|---|---|---|
| `versionName` | 界面展示用，`V主版本.次版本`，每版 +0.1 | V1.0 → V1.1 → V1.2 |
| `versionCode` | `主版本 × 100 + 次版本 × 10` | V1.0=100、V1.1=110、V1.2=120、V2.0=200 |

- `versionCode` 必须**严格递增**：客户端 `ApkUpdatePolicy.decide` 只比较它（`manifest.versionCode <= 本机`
  即视为无更新），Android 系统也不允许低版本覆盖安装。V1.0 取 100 而非 10，就是为了高于重置前的 42，
  已装 1.4x 的设备仍能收到 V1.0 的更新提示。
- 默认值写在两个 `app/build.gradle`（`android/`、`internal/mobile/`），也可用 `-PapkVersionCode=` /
  `-PapkVersionName=` 临时覆盖。后台「版本发布 → APK 更新」页会按当前公开清单自动预填下一版的 +0.1 / +10。
- 次版本满 9 后进主版本（V1.9 → V2.0，code 190 → 200），避免与 `×100 + ×10` 编码冲突。

## 4. 热更新构建与发布流程

1. 修改 `tools/backend-src/`。
2. 运行后端单元/契约测试。
3. 执行 `python tools/build_backend_zip.py`，它会同时更新 TV 和移动版 assets 中的 `python-backend.zip`。
4. 在本机启动后端并完成接口冒烟和浏览器验证。
5. 运行 `python tools/release_all.py --deploy`：部署网页版 `otv-web`（会先刷新豆瓣快照，再重建云端包与
   App 内嵌 zip），并顺带重生成首装离线目录种子 `assets/catalog_seed.json`
   （`tools/build_catalog_seed.py`，字段口径与 `VodRepository.decodeSnapshot` 一致；
   种子只影响 APK、不进热更包，所以刷种子后必须重打 APK，但不用发新热更版本）。
6. 重打两个 APK（`android`、`internal/mobile` 各跑一次 `.\gradlew.bat assembleRelease`）。
   **必须在第 5 步之后**——否则 APK 内嵌 zip 与刷新过快照的构建产物不一致。
7. 上传并发布热更：`node 后台管理系统/scripts/ops/hu-upload.mjs --name "…" --notes "…"`（默认站点最高版本 +1、立即发布）。
8. 追加 `docs/04-records/版本史.md` 与 `测试记录.md` 记录，再 `git add -A` → commit → `git push origin main`。
9. 发布后检查客户端静默更新、`:backend` 重启和关键页面回归。

> **2026-09-17 起用户长期授权全流程自动执行**（自动构建 APK、自动发布、自动更新文档、自动上传、自动推送）：
> 以上 5–8 步不再逐项征求「G3 明确确认」，做完直接汇报结果与证据。仓库根 `AGENTS.md` 有同一份约定。
> 仍要先问的只有不可恢复的破坏性操作，以及需要用户做产品取舍的改动。

> **每次对话收尾前检查一次有没有别的对话在改（2026-09-18 起用户要求，本仓库所有对话统一遵守）**：
> 做完改动、写最终回复之前，用 `codex_app` 的 `list_threads` 看本仓库（`D:\MyProjects\My TV`）
> 还有没有其它 `status=active` 的对话——**没有**就直接跑上面 5–7 步发布（不用再问用户）；
> **还有**就本次不打包、不构建 APK、不发布，只做「测试 + 文档 + 提交推送」，留给后面收尾的对话统一发布
> （它收尾时会再检查，那时没人改了）。发布前 `git status` 必须干净。
> 这样避免热更版本号抢占、半成品上线、APK 内嵌 zip 与构建产物不一致。**不要用定时任务替代这个检查。**
> 仓库根 `AGENTS.md` 有同一份约定。

热更新只替换后端和 `www/`，不替换原生 UI。坏包修复必须递增热更新版本号；验证包验收后应及时下线，避免误命中新装设备。

## 8. CloudBase 自定义域名（可选）

默认 `*.tcloudbase.com` 域名在部分 QQ/X5 内核浏览器中可能出现“风险提醒”中间页。该拦截发生在浏览器侧，服务器无法通过代码移除；如需消除，绑定一个你拥有且已备案的自定义域名。

前置条件：已登录 CloudBase CLI、拥有已备案域名，并准备好 SSL 证书（可先尝试平台自动申请免费证书）。当前环境为 `appletv-d5ge1bth794873f76`，默认域名仍被 App 使用，确认新域稳定前不要下线旧路由。

```bash
# 登录并绑定域名（以下以 tv.example.com 为例）
cloudbase login
cloudbase domains add tv.example.com -e appletv-d5ge1bth794873f76
cloudbase domains ls -e appletv-d5ge1bth794873f76

# 按 domains ls 输出的 CNAME 完成 DNS 配置后，再绑定四条路由（后台 /admin 有独立入口，默认域名仍可用）
cloudbase routes add -e appletv-d5ge1bth794873f76 --data '{
  "domain": "tv.example.com",
  "routes": [
    {"path": "/activate", "upstreamResourceType": "WEB_SCF", "upstreamResourceName": "activate"},
    {"path": "/hotupdate", "upstreamResourceType": "WEB_SCF", "upstreamResourceName": "hotupdate"},
    {"path": "/iptv", "upstreamResourceType": "WEB_SCF", "upstreamResourceName": "iptv"},
    {"path": "/web", "upstreamResourceType": "WEB_SCF", "upstreamResourceName": "otv-web"}
  ]
}'

# 验证页面与路由
curl -s https://tv.example.com/web/ | head -c 200
```

自定义域名只影响网页版入口，App 内嵌后端与后台管理都不依赖它。确认新域名稳定后，再按需清理旧通配路由；删除前必须检查激活链接、热更新和客户端内置地址。

### 9.2 CloudBase 兼容函数必须用自建 zip 上传

CloudBase CLI 3.8.1 在 Windows 上会把 `scf_bootstrap` 的换行改写成 CRLF，Linux 侧 shebang 变成
`#!/bin/bash\r`，容器以 `[./scf_bootstrap] no such file or directory` 退出，网关返回
`x-cloudbase-upstream-status-code: 443`（`tcb fn log`/`logs search` 能看到该错误）。

```powershell
python tools/pack_bridge_function.py --dir cloudfunctions/activate --output $env:TEMP\activate.zip
# 用官方 API 直传 zip：保留 LF 与 scf_bootstrap 的可执行位
$b64 = [Convert]::ToBase64String([IO.File]::ReadAllBytes("$env:TEMP\activate.zip"))
tcb api scf UpdateFunctionCode -e appletv-d5ge1bth794873f76 --json --body `
  '{"FunctionName":"activate","Namespace":"appletv-d5ge1bth794873f76","ZipFile":"' + $b64 + '","Publish":"false"}'
# 部署后自检：旧入口必须返回与 VPS 相同的响应体
curl -s -X POST -H "Content-Type: application/json" `
  -d '{"protocol":2,"action":"activate","code":"OTV-00000-00000","deviceId":"' + ("0"*64) + '"}' `
  https://appletv-d5ge1bth794873f76.service.tcloudbase.com/activate
```

`otv-admin`（Python，`fn code update` 实测保留 LF）与 `otv-web`（未在本次变更范围内）仍可用
原有 `tcb fn code update`。改 CloudBase 函数环境变量用
`tcb api scf UpdateFunctionConfiguration --body '{"FunctionName":"...","Namespace":"...","Environment":{"Variables":[]}}'`；
`tcb fn env` 只提供 `pull`，没有 push。
