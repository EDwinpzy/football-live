# 开发与发布手册

> 本手册描述“从本机改动到设备可用”的标准流程。架构细节见 [项目文档](../01-overview/项目文档.md)，历史证据见 [测试记录](../04-records/测试记录.md)。

## 1. 工作区约定

仓库根目录为 `D:\MyProjects\My TV`。除非需求明确限定端，功能改动默认覆盖 TV、移动版和网页版的共享部分。

| 目标 | 目录 | 说明 |
|---|---|---|
| TV APK | `android/` | Kotlin + Compose TV UI |
| 移动 APK | `internal/mobile/` | 触屏 UI，共享 data/playback/backend |
| 网页版源码 | `tools/backend-src/www/` | 与内嵌后端一起打包 |
| 网页云函数副本 | `cloudfunctions/otv-web/` | 部署包目录，不作为业务源码首选 |
| 内嵌后端源码 | `tools/backend-src/` | `proxy.py`、抓取、VOD、队标和 Web 资源 |
| 发布脚本 | `tools/` | 构建、同步、部署和数据维护 |

## 2. 先检查再修改

```powershell
Set-Location 'D:\MyProjects\My TV'
git status --short
python tools/sync_shared.py
```

发现已有未提交改动时，只修改当前需求涉及的文件，不使用 `git reset --hard` 或覆盖其他人的工作。

## 3. 按改动类型选择本地构建方式

### 3.1 只改后端或网页资源

适用于 Python、网页 HTML/CSS/JS、队标适配器、VOD 解析和资源文件：

```powershell
python -m unittest discover -s tools/backend-src/tests -p 'test_*.py'
python tools/build_backend_zip.py
python tools/build_web_function.py
```

本地后端冒烟：

```powershell
python tools/backend-src/proxy.py 8091
```

然后在浏览器验证网页功能；后端契约测试和浏览器验证结果分别追加到 `docs/04-records/测试记录.md`。

### 3.2 改 Kotlin/Compose 或播放器原生代码

先检查共享层：

```powershell
python tools/sync_shared.py
```

再分别构建，禁止两个工程并行构建：

```powershell
Set-Location 'D:\MyProjects\My TV\android'
.\gradlew.bat assembleRelease

Set-Location 'D:\MyProjects\My TV\internal\mobile'
.\gradlew.bat assembleRelease
```

原生代码无法通过后端热更新替换，必须安装新 APK。

## 4. 热更新构建与发布流程

1. 修改 `tools/backend-src/`。
2. 运行后端单元/契约测试。
3. 执行 `python tools/build_backend_zip.py`，它会同时更新 TV 和移动版 assets 中的 `python-backend.zip`。
4. 在本机启动后端并完成接口冒烟和浏览器验证。
5. 使用 `python tools/release_all.py` **只生成本地部署包和热更新 zip**；确认本地构建产物、版本和校验值。
6. 将本地构建结果和拟发布范围报告给用户；未获 **G3 明确确认** 前，不部署云函数、不上传热更新、不推送 APK 或远程 Git。
7. 用户明确确认后，才运行 `python tools/release_all.py --deploy` 部署网页版；再到后台“热更新”页选择“仅上传、立即发布或定时发布”。
8. 发布后检查客户端静默更新、`:backend` 重启和关键页面回归。

热更新只替换后端和 `www/`，不替换原生 UI。坏包修复必须递增热更新版本号；验证包验收后应及时下线，避免误命中新装设备。

## 7. 安全边界

- 私钥、卡密 CSV、服务密钥、Cookie 和长期令牌不得进入 Git、云端部署包或文档。
- 播放源和第三方素材必须记录来源与授权边界；非商业素材不能默认推断为可商业使用。
- 变更公网接口、RLS、后台权限或热更新校验时，必须增加对应契约测试并记录回滚方式。

## 8. CloudBase 自定义域名（可选）

默认 `*.tcloudbase.com` 域名在部分 QQ/X5 内核浏览器中可能出现“风险提醒”中间页。该拦截发生在浏览器侧，服务器无法通过代码移除；如需消除，绑定一个你拥有且已备案的自定义域名。

前置条件：已登录 CloudBase CLI、拥有已备案域名，并准备好 SSL 证书（可先尝试平台自动申请免费证书）。当前环境为 `appletv-d5ge1bth794873f76`，默认域名仍被 App 使用，确认新域稳定前不要下线旧路由。

```bash
# 登录并绑定域名（以下以 tv.example.com 为例）
cloudbase login
cloudbase domains add tv.example.com -e appletv-d5ge1bth794873f76
cloudbase domains ls -e appletv-d5ge1bth794873f76

# 按 domains ls 输出的 CNAME 完成 DNS 配置后，再绑定四条路由（/admin 已随后台下线移除）
cloudbase routes add -e appletv-d5ge1bth794873f76 --data '{
  "domain": "tv.example.com",
  "routes": [
    {"path": "/activate", "upstreamResourceType": "WEB_SCF", "upstreamResourceName": "activate"},
    {"path": "/hotupdate", "upstreamResourceType": "WEB_SCF", "upstreamResourceName": "hotupdate"},
    {"path": "/iptv", "upstreamResourceType": "WEB_SCF", "upstreamResourceName": "iptv"},
    {"path": "/web", "upstreamResourceType": "WEB_SCF", "upstreamResourceName": "otv-web"}
  ]
}'

# 验证页面与路由
curl -s https://tv.example.com/web/ | head -c 200
```

自定义域名只影响网页版入口，App 内嵌后端与后台管理都不依赖它。确认新域名稳定后，再按需清理旧通配路由；删除前必须检查激活链接、热更新和客户端内置地址。
